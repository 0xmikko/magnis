## The Goal

1. After initial synchronization, Graph contains 100% of the post IDs returned by the completed accessible timelines of authors selected through Track on X.
2. After a restart and two identical polls, there are zero duplicate posts and zero missing IDs among newly returned posts; an unchanged forward poll reads zero historical continuation pages.
3. When X returns a 429 with reset time T, Accounts remains paused until T, then resumes with zero cleared or duplicated posts.

## Why now

Now the X Source reads only ten recent posts per tracked handle every five minutes, without historical pagination or an incremental provider checkpoint.

The inspected catalog base is `8f1e371`.
The reference conversation is Codex session `01a0c40c-b093-7e60-9eb2-9978a058aa18`.
The owner narrowed this plan to posts: «давай только посты возьмем».

## The target

### Scope and provider boundaries

Read public posts only for the existing Track on X set.
Retain the X profiles needed to identify those authors and link their posts to existing tracked contacts.
Do not import following, followers, new contacts, ordinary DMs or encrypted X Chat.
No new inbox, sending tools, OAuth connection flow or app credential-maintenance work belongs to this scope.

Keep the current app-only `bearer_token`, the `x` surface and the host's existing Poll worker.
An empty tracked set performs zero provider requests.
A missing credential or rejected API entitlement remains a visible error.

[User timelines](https://docs.x.com/x-api/posts/timelines/introduction) expose up to 3,200 recent posts per author.
Complete history means the accessible API window, not every post ever published.
Previously imported posts remain when they leave that window.
A missing item in a limited provider response is not a deletion.
Preserve the existing handling of replies and reposts.

### Historical import and regular updates

Extend `XClient.recentTweets` and `fetchX`; do not introduce a second client or scheduler.
Resolve only tracked handles to immutable provider user IDs.
Use real `pagination_token` values to drain each author's accessible history.
Start with one author timeline page per Source response and at most one author identity lookup when required.
Rotate unfinished authors between responses so one long timeline does not consume all initial work.
Retain the current five-minute regular poll interval.

Replace the incremented numeric cursor with opaque per-author continuation and committed forward state.
A legacy numeric cursor starts the new historical walk once while reusing existing Graph anchors.
Invalid new cursor state is an error, never a silent restart.
Tokens and checkpoints belong to the current tracked set and immutable author IDs.

Capture the newest returned post ID when a historical or forward walk begins.
Keep that candidate separate from the last fully committed checkpoint.
Do not advance the committed checkpoint before every continuation page in that walk has been admitted.
A normal empty timeline is a validated provider result and has no fabricated post ID.

After historical completion, use `since_id` and drain every forward continuation page.
A poll with no newer posts does not reread the author's historical pages.
Posts arriving during historical import are picked up after completion using the captured boundary.
Initial completion precedes regular catch-up; no continuous-delivery guarantee is made during quota-limited initial import.

All provider user and post IDs remain strings.
Do not convert Snowflake IDs to JavaScript numbers or invent numeric `traversed` ranges.
Keep continuation and forward checkpoint in the existing SDK fetch/progress contract.

A newly tracked author receives accessible history.
A removed author receives no further timeline requests; imported posts survive.
A provider-confirmed handle change preserves the immutable profile anchor and post history.
If a tracked handle cannot be resolved, surface the failure; never report that author's walk as successfully complete.

A fetch, conversion, contact-link or Graph admission failure leaves the committed cursor unchanged.
Replaying the last page is safe.
A provider-confirmed expired continuation restarts only the affected author walk.
Reuse its saved boundary and already admitted anchors, retaining other authors' completed state.
Forward reads inherit the provider's accessible-window limit.
Do not claim recovery of posts that disappeared before polling; coverage beyond returned API pages remains unverified.

### Graph and existing reads

Continue using `x.profile`, `x.post`, `x:profile:<user_id>` and `x:post:<post_id>`.
Preserve `fullText`, article titles/bodies, media and URL references, provider creation time, metrics and reply/repost classification.
Preserve the existing `authored_by` and contact `identity` relations.
Profile linking failures must fail admission instead of being swallowed.
Reuse the existing tracked-contact lookup and placeholder-name update; do not create new people.

Later timeline pages must link to the same author even when its profile was admitted on an earlier page.
Reuse existing Graph anchor lookup and batch admission.
Normalize duplicate remote IDs within a page before writes and progress accounting.

Apply the author and platform filters of `x.posts.list` before pagination.
A filtered page and its total represent the selected author/platform, even when unrelated posts are newer.
The existing X feed and read tools remain the user entry points.
No UI redesign or new entity schema is required.

### Progress, errors and evidence

Keep the existing profiles/posts progress declaration.
Replace the ten-post estimate with counts of unique admitted work.
The provider's all-time tweet count is not an exact accessible target.
Bootstrap stamps each profile and post once per generation; page replay does not restate it.
Catch-up adds only actual creates; updates and repeats contribute zero new-item deltas.
Complete the target only when every selected author walk has drained; equal intermediate counts do not imply completion.
Retained posts outside the accessible window are never swept.

Validate provider bodies rather than casting unknown JSON or converting a dropped/malformed response to an empty timeline.
A documented successful empty timeline remains valid.
Required fields, array members, pagination metadata and requested media references are checked before admission.

For HTTP 429, honor a valid Retry-After or the documented `x-rate-limit-reset`.
Missing or malformed provider timing is an error.
An untimed credits-depleted HTTP 402 is an actionable error, not an invented sixty-second hold.
After a fatal response, that Source call starts no further provider requests.
The host owns the durable hold and retry deadline.
Do not change error codes or SDK wire contracts accidentally.

Reuse `acceptance/telegram-performance` for a separate manual X report.
Its grouping already accepts arbitrary Source IDs.
Add `X_FIXTURE_FILE` to the existing real-provider guard.
Record exact app/catalog/installed-package revisions, imported counts, pages, holds and fetch/admission/wall time.
Record initial import, restart, unchanged poll and synchronization of a new post.
A speedup claim requires equivalent same-account measurements.
Live Twitter and PostgreSQL work stays outside CI; preserve the saved Telegram/Google data and credentials.
